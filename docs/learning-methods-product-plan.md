# 用户自带资料、解题方法与个人笔记

状态：平台入口已改为用户上传。作文工作台保留原题、三段编辑和个人模板，新增“本题作答／我的模板”独立草稿、成稿预览后显式应用、专注及小屏切换。翻译工作台保留固定 GitHub 方法导入、个人 TXT/MD 资料和对照笔记，新增方法 ID 关联与历史应用、译文预览后应用、方法 RAG 与显式授权的个人笔记辅导。`learning.html` 已支持跨试卷查找、隐藏结果重练、Markdown 导出、JSON 备份合并恢复；表达库可在工作台收藏并插入自己的句子。原卷题型旁及顶部入口保留，首次空白带入原文不覆盖草稿；只有确认应用才更新已验证的本题答案。继续使用 PDF 图片＋文字坐标＋SVG 标注＋Question Layer，不另建阅读器。

未实现：任意仓库导入、逐卡个人修订／禁用、原文选区／方法／错因完整双向关联、听力时间点笔记、自动间隔复习、登录、云同步和多用户隔离。当前提示下一步是一次显式 AI 请求，不是自动追踪教学步骤的系统。下面区分已实现能力与后续设计。

## 1. 两个项目怎样结合

不是合并两个网站，而是让试卷平台使用另一个仓库中的学习方法。

已实现来源：[CET6-Translation-Notes](https://github.com/TanGuilin520/CET6-Translation-Notes) 的 `master/翻译.md`。用户点击“加载 GitHub 笔记”才发起固定文件下载，后续点击可刷新；进入页面的 GET 只读取本机缓存。接口不接受任意网址，不在普通聊天或阅读时自动抓取，也不调用 AI。

实际内容以 [`翻译.md`](https://github.com/TanGuilin520/CET6-Translation-Notes/blob/master/%E7%BF%BB%E8%AF%91.md) 为准，按真实的二级编号标题切成“是”“的”“有”“随着”、时态、被动、定语从句、语序等方法卡，三级“注意／类型／例句”保留在所属章节正文。检查时 Markdown 有 18 个实际章节，而来源 README 介绍 19 类；系统不会按宣传数字补造不存在的第 19 节。前端目录仍是关键词查找；AI 请求的服务端检索另采用选定方法 ID 精确命中加本地词汇／哈希向量补充，两者不混称外部语义 Embedding。

当前方法卡提供 `id / title / category / bodyMarkdown / keywords`，源文件保持原文，不让 AI 改写例句或猜测适用范围；来源记录文件链接、加载时间和 SHA-256。右侧展示整理者“糯糯不爱吃糖”、四六级邹老师课程及仓库维护归因，明确“个人学习资料，非官方解析”。完整源文只保存在 Git 忽略的 `data/learning-methods/` 运行缓存，不放进 `public/` 或随公开平台代码分发；资料自身的权利不因平台公开而改变。

“GitHub 总结”和“我的资料”分开浏览，后者仍支持粘贴／严格 UTF-8 TXT/MD 导入与编辑保存，前者加载不会替换个人资料。编号的个人方法也能分节显示，普通自由文本仍可直接保存。逐卡修订／禁用、结构化适用场景／步骤／限制和用户修订记录尚未实现，应在后续通过独立个人修订层增量增加；个人总结不能作为自动替换规则。

例如“随着”卡片引导用户比较 `As + 完整句子` 与 `With + 名词短语`，结合句子选择，而不是遇到“随着”就强制替换。

## 2. 从用户角度设计流程

当前可用流程：

1. 上传自己的试卷，答案和音频可选。
2. 点击原卷对应翻译位置的蓝色题号，直接进入工作台；无题号时通过可确认的题型标题入口进入原页。
3. 没有本题笔记或草稿、且尚未编辑时，带入可确认的中文原文；有真实题号时将本题已有作答带入初译。恢复的笔记／草稿及用户刚输入的内容优先，不把答案册解析充当原文，不读取其他题作答。
4. 左侧加载指定 GitHub 总结，或切换“我的资料”；搜索并选择方法，右侧对照说明、例句及自己的历史应用，中间保留练习空间。小屏切换练习／方法／资料，作文也提供编辑／模板／预览切换及专注模式。
5. 写初译、修改、原因或自由笔记；“记录本次使用”追加名称并保存 `{source,id,title}` 方法关联到草稿，正式保存仍需点击。可收藏自己的表达（分类、标签、来源、例句），在当前编辑位置插入；本机表达库最多 500 条。
6. 按需点击“提示下一步／检查译文／方法分析”；个人方法和历史笔记须勾选本次授权才提供，当前原文与译文仍属于用户请求内容。撤销授权后清除后续对话上下文，已发出的请求无法撤回。AI 只建议，不替用户保存笔记或答案。
7. 作文与翻译先预览成稿再显式确认“应用到本题”：只有真实题号、题型及版本仍可确认才写 `answers`，覆盖需确认，与其它题作答及标注合并。页码入口或独立练习不能虚构题号提交，仍可保存草稿／笔记；返回时恢复原题或原页。
8. 在 `learning.html` 按类型／试卷及关键词、标签、方法查找记录；先隐藏结果重练并保存本次尝试，再展开对照。支持筛选记录 Markdown 与 JSON 整库备份，恢复前预览并确认合并。

当前 AI 可按选定方法分析，并要求不适用时说明；方法卡也可查看已保存的历史应用。自动适用性评分、连续教学步骤与原文选区／错因的完整双向关系仍属后续，不把一次生成当成完善的教学规划系统。

学习模式可提供逐步提示；自主作答时不要自动展示答案。方法集按模块配置，支持临时更换，不强迫所有题目使用一套规则。

| 模块 | 方法入口 | 最有价值的笔记 |
| --- | --- | --- |
| 翻译 | 句型、主谓、时态、语序方法卡 | 原句／初译／修改／错因／所用方法 |
| 阅读 | 定位、同义替换、排除干扰项 | 原文证据／我的判断／错误选项的原因 |
| 听力 | 预读、信号词、预测和精听策略 | 音频时间点／没听懂的表达／重听发现 |
| 写作 | 段落结构、论证方法和现有填空模板 | 好用表达／改写对照／模板适用条件 |

## 3. 笔记应该更丰富，但更少打断

已有：阅读器选区工具条、自由笔记、可选标签、6000 字、独立多草稿、撤回重做和返回原文；翻译六项可选对照字段增量保存 `methodRefs`，方法卡按来源＋ID 查历史笔记。作文的本题草稿与复用模板隔离，本题草稿最多 200 个上下文。学习记录页汇集试卷标签笔记、翻译对照、作文草稿／成稿和表达。方法关联是笔记层关系，不等于已经自动关联到具体 PDF 选区或建立完整错误分类。

### 阅读过程中：已有与后续边界

- 选中原文 → 点击笔记 → 自动带上试卷、页码、选区和可确定的题号，光标直接进入正文。
- 默认自由笔记；可选“翻译对照／错因／句型／方法应用”轻量模板。没填的字段不妨碍保存。
- 后续可给 AI 回复增加“保存这段建议”；当前不自动创建笔记或发送全部历史笔记给模型。
- 翻译保存“我的初译 → 修改结果 → 为什么”；复习时可以隐藏结果，重新尝试后再展开。
- 听力“记下此刻”及按笔记回放仍未实现；ASR、自动题目分段同样不在当前能力内。
- 写完收起编辑器，不同时把笔记、AI、方法面板全部展开；阅读空间优先。
- 颜色可以用于用户自定分类，但不要假设某种颜色必然代表某个错因。

### 复习过程中：当前可用

- `learning.html` 按记录类型、试卷筛选，关键词框匹配原句、内容、标签和方法名称；错因可作为文字查找，尚无独立结构化错因筛选器。
- 笔记返回有定位的原卷位置；方法卡展示来源＋ID 对应的应用记录。作文、翻译记录可继续编辑。
- 重练模式隐藏修改稿／成稿／笔记对照，用户先输入并保存本次尝试，再自行展开；重练不修改原笔记或试卷答案，当前没有定时提醒和间隔调度。
- Markdown 导出当前筛选记录的完整内容，即使开启重练也不隐藏修改稿；JSON 备份包含学习白名单分区，可能有个人资料、作答与对话内容，请妥善保存、不要公开上传。
- 恢复仅接受 UTF-8、版本 1、最大 8MB 的本平台备份；先校验及预览，确认后触发下载恢复前备份，再按分区／记录标识合并，同 ID 采用备份版本，不删除未包含记录。写入失败尝试回滚并说明回滚失败情况；恢复前关闭其它编辑页，并确认备份下载已保存。

## 4. 技术上的连接边界

答案资料和学习方法是两种不同知识，不混成一个未经标识的索引：

- 答案库：保留 Question ID 精确检索＋向量补充，回答“题目依据和明确答案是什么”。
- 方法库：只读已校验的固定 GitHub 本机缓存，选定方法 ID 精确优先，再以英文词汇／中文双字词重叠和 256 维本地哈希向量补充，回答“可以怎样做”。没有第三方向量数据库或付费语义 Embedding；哈希向量不代表真正的语义理解。
- 个人方法／笔记：仅来自本次客户端明确授权、限量提供的资料；关联方法及词汇命中辅助排序，服务端不读取浏览器全部记录或其它用户笔记，也不冒充官方答案。当前没有账号、租户过滤或云端私人知识库。

每条引用说明来源：“上传答案资料”“我的翻译方法：随着”“我的错因笔记”“AI 辅助分析”。资料缺失或方法不适用时直接说明，不能补造官方依据。

题目 scope 启用现有 LangGraph sidecar 时，检索节点消费主服务已检索且限量的学习证据，并记录 `retrieve_methods`、`retrieve_personal_notes` 只读工具活动；学习引用独立于官方答案依据。未配置 sidecar 时保留原主服务路径，自由／选段 scope 仍由主服务直连，不宣称所有对话都走 LangGraph。翻译支持 hint／review／method；无可用模型 Key 时明确不生成辅导，不伪造纠错或把整份答案作为提示回退。模型不直接写答案或笔记，任何应用仍须用户确认。

当前资料 API 为缓存只读 `GET /api/learning-methods/translation-notes` 和显式更新 `POST /api/learning-methods/translation-notes/refresh {}`；下载限定固定公开 HTTPS 文件、重定向来源、256KB、8 秒和严格 UTF-8。失败保留旧缓存，不暴露代理凭证。用户主动发起辅导时才以 `learningContext` 指定方法与授权，方法证据独立进入 AI 上下文，不改动答案 RAG 索引，也不提升“存在官方解析”的判断。服务端验证授权和各字段上限，个人资料不会因为选中公开方法就自动发送。

后续结构化方法卡可增量扩展适用场景、步骤、限制和个人修订；现有笔记保留题号／页码及 `methodRefs: [{source,id,title}]`，旧笔记无关联字段仍可读取。选区错因双向关系及 `audioTime` 是后续扩展，不把它们当作现有记录必填字段。保存与应用增量合并最新试卷状态，Reader 对答案基线作比较并提示同题跨窗口冲突，不以旧整卷缓存静默覆盖新答案。

## 5. 推荐开发顺序

已完成固定学习资料导入、方法原文与历史记录、两类工作台显式应用、表达库、跨试卷查找／重练／导出、方法检索与授权笔记辅导。推荐后续顺序：

1. 独立个人修订／禁用层与方法适用场景，保持源文和个人修订可区分。
2. 具体原文选区／方法／结构化错因双向关系，及听力时间点笔记。
3. 用真实匿名化样本评估检索相关性与提示安全性，再考虑语义向量服务、连续教学规划和用户自选间隔复习。

验收以真实体验为准：首次上传不依赖默认内容；提示不提前泄露完整译文；方法可修订；保存不打断输入；刷新草稿不丢；搜索可找回；引用不混淆个人总结与答案资料。

当前没有登录、租户隔离或云同步。“用户上传”仍是本机单用户平台，不等同于可直接公开提供多用户服务；公网部署前需增加鉴权与文件访问隔离。
